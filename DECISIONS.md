# DevFlow — Decisions

**Track selected:** Part 2 — The Premium Home Page

## 1. Why this approach over the obvious alternative?

I built DevFlow as a React + Vite single-page product concept. I chose a component-based frontend with custom CSS because it let me move quickly while still keeping direct control over layout, responsiveness, and interactions.

Since the first question in the brief refers to an “ingestion strategy,” which applies to Part 1, I interpreted it for my selected Part 2 track as the implementation strategy I chose over the main alternative.

The alternative I considered was using a UI component library or a pre-built landing-page template. I rejected that because much of the challenge is about UI judgment and visual craft. Building the interface myself gave me more control over spacing, hierarchy, responsive behavior, and the overall product feel.

## 2. Trade-off under the time limit

I prioritized a polished core experience over adding many features or animations. The page includes a focused hero, a product dashboard preview, feature and workflow sections, responsive layouts, and restrained hover interactions.

Given a full week, I would improve accessibility, extract the larger sections into reusable React components, add more detailed mobile testing across devices, improve keyboard navigation, and add one purposeful interactive product demonstration rather than simply adding more visual effects.

## 3. AI usage and personal verification

I used AI as a development assistant for layout ideas, React/CSS implementation suggestions, responsive styling, and reviewing the assignment requirements.

I personally created and ran the project, integrated the suggested code, checked the layout in the browser, tested the 390px responsive view, verified the desktop experience, pushed the code to GitHub, and deployed the application through Vercel.

I also reviewed the copy to avoid fabricated testimonials, user counts, customer logos, or unsupported claims. The dashboard values shown in the product preview represent mock workspace state rather than claims about real DevFlow users.

Most importantly, I reviewed the implementation so I can explain the structure, styling choices, responsive behavior, and decisions made in the project.
